# 투자심사보고서 (대출·지급보증) 작성 양식

사내 표준 심사보고서 양식이다. **차주(Borrower) + 신용보강 제공자(지급보증인/모회사)** 구조의 여신 건을 전제로 하며, 서식(Word 스타일), 목차 구조, 문장 작성 규칙 세 가지를 모두 규정한다.

## 작업 순서

1. **자료 수집 먼저.** 재무제표·공시·신평사 리포트·증권사 리서치·업황 자료를 모두 확보한 뒤에 문서를 만든다. 숫자 없이 목차부터 채우지 않는다.
2. **누락 정보는 즉시 질문.** 금리·수수료·만기·참여금액 등 딜 조건, 차주/보증인 확정, 기준일자는 추정하지 말고 사용자에게 물어본다. 확정 전 항목은 원문 관례대로 `[TBD]`, `[5.9]%` 처럼 대괄호로 표기한다.
3. **구조 설계.** `references/structure.md` 의 표준 목차를 딜 성격에 맞게 가감한다.
4. **문서 생성.** `scripts/memo_builder.py` 로 `assets/template.docx` 기반 문서를 만든다. 스타일을 직접 만들지 말 것 — 템플릿의 `(투자계획서)*` 스타일을 쓴다.
5. **검증.** 아래 체크리스트를 돌린 뒤 파일을 전달한다.

## 문서 생성 방법

```python
import sys; sys.path.insert(0, "<skill경로>/scripts")
from memo_builder import Memo

# 표제지(딜명 26pt 네이비 + 주황 구분선 + 작성월) → 목차 페이지 → 본문 순으로 자동 생성
m = Memo("㈜두산 해외자회사 HyAxiom, Inc. 대출", "2026. 03.")
# m = Memo(..., cover=False, toc=False)   # 표제·목차 없이 본문만 만들 때
# m.toc(levels=3)                          # 목차에 제목3까지 넣을 때 (기본은 제목2까지)

m.h1("Executive Summary")                    # (배)제목1  — 대단원, 파란색 14pt, 자동번호 1. 2. 3.
m.h2("주요 금융 조건")                        # (배)제목2  — 중단원, 파란색 12pt, 자동번호 1.1
m.h3("재무적 취약성")                         # (투자계획서)제목3  — 소단원, 검정 볼드, 자동번호 1.1.1
m.sub("[실질 위협 분석]")                     # (배)소제목 — ✓ 불릿 볼드
m.body("(사상 최대 실적 달성) 2025년 ... 규모임.")  # (투자계획서)본문
m.table_title("[별도기준 손익계산서 요약]")     # (배)표 제목 — 표 바로 위, 가운데, 볼드
m.unit("(단위: 억원)")                        # (배)단위   — 표 우측 상단
m.data_table(("구분","2023","2024","2025"), rows)   # 재무 데이터표
m.cond_table([("차주","HyAxiom, Inc."), ...])       # 조건표/개요표(2열)
m.verdict_table([("수익성", "...", "..."), ...])     # 종합평가표(구분/주요내용/시사점)
m.source("출처: ㈜두산 IR자료, NICE신용평가")  # (투자계획서)출처   — 표 아래 9pt
m.company_profile(회사명="㈜두산", 본사주소="...", ...)  # 기업개요표(8개 항목 고정)
m.appendix("[별첨1] HyAxiom 재무제표")        # 번호 없는 제목1

m.save("투자계획서_<딜명>_v<날짜>.docx")
```

`python-docx` 가 없으면 `pip install python-docx --break-system-packages`.

차트·구조도 이미지는 `m.doc.add_picture(path, width=...)` 로 삽입하고, 바로 위에 `table_title`, 바로 아래에 `source` 를 붙인다.

**목차는 Word 필드로 들어간다.** 템플릿에 `updateFields=true` 가 설정되어 있어 Word에서 문서를 열면 목차가 자동으로 채워진다(열 때 "필드를 업데이트할까요?" 대화상자가 뜨면 예). 수동 갱신은 목차 클릭 후 F9. LibreOffice나 미리보기에서는 자리표시자 문구만 보일 수 있으므로, 최종본은 반드시 Word로 한 번 열어 목차를 확정한다.

## 핵심 규칙 요약

**표제지·목차** — 표제지는 딜명(KoPub Bold 26pt, 색 #002060) + 주황 구분선(#F58220) + 작성월(Bold 14pt)로 구성하고, 다음 장에 `목차`(Bold 20pt) + TOC 필드를 넣는다. 머리글의 딜명은 표제지와 항상 동일해야 한다.

**구조** — 대단원은 항상 이 5개 + 별첨: `Executive Summary` → `Investment Highlight` → `리스크 분석` → `지급보증인(OOO) 분석` → `차주(OOO) 분석` → `그룹 주요 계열사 분석`. 회사 분석 단원은 예외 없이 `회사 개요 / 산업 분석 / 사업 분석 / 재무 분석` 4단 구성. 상세는 `references/structure.md`.

**문체** — 본문 문단은 `(핵심 메시지) 근거 서술...` 형태로 쓴다(원문 291개 본문 중 251개가 이 형태). 어미는 `~함 / ~임 / ~음 / ~됨` 으로 끝내고 `~습니다`, `~한다` 를 쓰지 않는다. 아래 4가지를 반드시 지킨다.
- **괄호 소제목에 시사점을 담는다.** 분류 라벨·추상명사가 아니라 숫자·결론·판정을 넣는다. 10~25자 기준이며, 짧게 만들려고 시사점을 버리지 않는다. (○ `(수출 비중 65.3% 기록)` / × `(비중 상승)`)
- **두괄식**: 괄호 다음 첫 문장이 결론이다. 배경·경위를 앞에 깔지 않는다.
- **문단당 2~3문장**을 넘기지 않는다. 4문장 이상이면 문단을 쪼갠다. 5개 이상 병렬되면 표로 옮긴다.
- **문어체**: 구어체 연결·부사(그런데, 사실, 결국, 좀)를 쓰지 않는다.
- **번역투를 쓰지 않는다.** ① 지시대명사로 앞 문장 되받기(`그 지위는 ~한 결과임`) ② `A라는 B` 동격(`인허가와 수가라는 제도적 관문`) ③ 문두의 `A가 아니라 B` ④ 명사구 사슬(`~에 있음에서 비롯된 것으로`). 넷 다 **문장을 끊고 주어를 다시 세워** 해결한다.
- **보고서가 자기 자신을 설명하지 않는다**: 구성·목차·서술 방식 해설(`본 장은 ~를 네 개 축으로 기술함`), 구성 체계표, 작업 지시 문구를 본문에 넣지 않는다. 확인 필요 항목·도표 출처·보완 계획 같은 작성자용 메모는 배포용 문서와 분리해 별도 내부 노트로 관리한다.

상세는 `references/style-guide.md`.

**표** — 표 위에 `[제목]`, 우측에 `(단위: OO)`, 아래에 `주1) ` 와 `출처: `. 숫자는 천단위 콤마 + 우측정렬. 상세는 `references/formatting.md`.

**리스크 단원** — 각 리스크 항목은 반드시 `[실질 위협 분석]` 과 `[리스크 완화 기제]` 한 쌍으로 서술한다. 리스크를 인정하고 곧바로 완화 논리를 붙이는 것이 이 양식의 핵심 설득 구조다.

**설득 구조** — 자료 나열이 아니라 논증이다. ① `제목2` 단원 첫머리에 결론을 3~4문장으로 제시하는 요약 단락을 둔다(괄호 소제목 없음). ② 긴 분석 단원은 `소결 및 시사점` 으로 닫고 마지막 문단을 `(결론)` 으로 시작한다. ③ 수치를 제시했으면 그 의미를 반드시 이어 쓴다(사실 → 해석 → 함의). ④ 리스크 단원은 `투자 안전성 분석` 처럼 무엇이 투자금을 지키는가를 묻는 제목으로 세운다. ⑤ `~로 판단됨`, `~가 핵심 안전판임` 처럼 작성자의 판단을 명시하고 독자에게 해석을 떠넘기지 않는다. 상세는 `references/style-guide.md` §7.

**출처** — 모든 수치와 표에는 출처를 단다. 근거 없는 숫자를 쓰지 않는다.

## 최종 체크리스트

- [ ] 모든 표에 `[표 제목]` / `(단위: OO)` / `출처: ` 3종 세트가 붙어 있는가
- [ ] 표기가 `출처: ` / `주1) ` / `(단위: 억원)` 로 통일돼 있는가 (콜론 뒤 한 칸)
- [ ] 본문 문단이 `(소제목) 서술` 형태이고 어미가 `~함/~임/~음/~됨` 인가
- [ ] 괄호 소제목만 훑어도 논지가 서는가 (라벨·추상명사만 남아 있지 않은가)
- [ ] 각 문단이 2~3문장 이내이고, 첫 문장에 결론이 있는가
- [ ] 번역투가 남아 있지 않은가 (`그 지위는`·`~라는`·문두 `아니라`·`비롯된 것으로`)
- [ ] 문서 구조를 설명하는 문장·표, 작성자용 메모(확인 필요 항목·출처 링크)가 본문에 남아 있지 않은가
- [ ] 리스크 단원의 모든 항목에 `[실질 위협 분석]` + `[리스크 완화 기제]` 가 있는가
- [ ] Executive Summary의 금액·금리·만기가 본문 및 조건표와 일치하는가
- [ ] 재무 수치가 원자료(공시·IR·신평사)와 일치하고 기준일자가 명시되어 있는가
- [ ] 미확정 조건이 `[TBD]` 형태로 표기되어 있는가
- [ ] 머리글의 딜명, 표지 2줄, 파일명이 서로 일치하는가
- [ ] 사용된 스타일이 전부 `(투자계획서)*` 인가 (Normal 문단이 남아 있지 않은가)
- [ ] Word로 열어 목차를 갱신했고, 목차의 쪽번호·제목이 본문과 일치하는가
- [ ] 제목 자동번호가 `1. → 1.1 → 1.1.1` 로 이어지는가 (별첨만 번호 없음)

검증은 생성한 docx를 다시 열어 `p.style.name` 을 순회하거나, `soffice --headless --convert-to pdf` 로 렌더링해 눈으로 확인한다.

## 원본 양식의 알려진 결함 (재현하지 말 것)

기준이 된 원본 문서에 아래 문제가 있었고, 이 스킬의 템플릿은 모두 고쳐진 상태다. 기존 문서를 이 양식으로 재편집할 때도 같이 확인한다.

- **제목 번호가 목차와 본문에서 달랐다.** 제목1과 제목2·3이 서로 다른 다단계 목록에 묶여 있어 본문이 `1.1 … 1.8`로 흘렀다. 템플릿은 세 레벨을 같은 목록에 연결했다.
- **제목3이 목차에 잡히지 않는다.** `(투자계획서)제목3`은 `(투자계획서)본문` 기반이라 개요 수준이 없다. `Memo.toc(levels=3)` 이 필요할 때만 부여한다.
- **표 너비 9781 dxa 가 본문 폭(9747)보다 넓었다.** 템플릿은 9747로 맞췄다.
- **별첨 파트가 `Normal` 스타일 + `~합니다` 체로 작성돼 있었다.** 별첨도 본문과 같은 `(투자계획서)*` 스타일·개조식 어미를 쓴다.
- **기업개요표 항목 수가 회사마다 6~8개로 달랐다.** `Memo.company_profile()` 은 8개 항목을 고정 순서로 강제한다.
- **소단원 명칭이 `종합평가 / 종합 평가 / 종합의견`, `수익성분석 / 수익성 분석` 으로 갈렸다.** 이 스킬은 `수익성 분석 / 재무상태 분석 / 현금흐름 분석 / 종합평가` 로 통일한다.
- **표기가 갈렸다** — `출처 :` 62회 vs `출처:` 28회, `주1:` vs `주1)`, `(단위: )` vs `(단위 : )`. 이 스킬은 **콜론 뒤 한 칸**으로 통일한다: `출처: ` / `주1) ` / `(단위: 억원)`.
